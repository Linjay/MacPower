# MacPower 产品设计 v0.1

设计日期：2026-09-23。状态：已选定方案 1 · Power Path，已实现原生 0.1.0 本机开发版。本文保留产品目标与验收要求；当前实现和验证范围以 [原生实现](native-implementation.md) 与 [原生验收](native-acceptance.md) 为准。

## 1. 产品定义

MacPower 是常驻 macOS 菜单栏的电源观察工具，让用户在几秒内回答三个问题：**现在靠什么供电、多少功率进入电池或从电池流出、Mac 自己用了多少电。** 电池健康与历史趋势用于解释长期变化。

主要面向使用 MacBook、经常在充电器、显示器供电、扩展坞与电池之间切换的用户。优先适配 Apple Silicon MacBook；目标最低 macOS 14，属于本产品的计划兼容范围，不是已完成的兼容声明。Intel、无内置电池的桌面 Mac 和 UPS 作为后续独立能力范围。

“电池运行的功率”拆成两个清晰指标：电池向外提供的放电功率，以及整机当前耗电。不能将二者在所有供电状态下视为相同。

## 2. 核心使用场景

| 用户问题 | 首屏回答 | 进一步操作 |
|---|---|---|
| 插上 65 W 电源，究竟充进去多少？ | 供电能力 65 W；当前输入 61.6 W；充入电池 +27.6 W | 点击指标了解口径 |
| 为什么插着电仍在掉电？ | 外接电源供电，同时电池放电；显示两路流向 | 查看近期输入、耗电和放电趋势 |
| 电池模式下，现在耗电高不高？ | 电池放电功率与近期曲线；没有适配器占位大卡片 | 打开 1 小时趋势比较自己的前后变化 |
| 插电但不充电是否异常？ | 区分已充满、系统明确暂停、原因未知 | 查看系统电池设置；不猜测具体原因 |
| 电池是否健康？ | 系统报告最大容量、状况、循环次数 | 查看容量变化与指标解释 |

首版不做应用耗电归因、充电控制、AI 诊断、外设电池大全或电费计算。每个功能都以可获得且可解释的数据为边界。

## 3. 指标契约

| 用户名称 | 含义与优先来源 | 展示规则 | 缺失与限制 |
|---|---|---|---|
| 供电能力 | 系统报告的当前适配器/连接供电档位，来自适配器详情 | 整数 W，注明“系统报告” | 不叫实时输入、不冒充铭牌额定值、不据此判断线材额定能力 |
| 电源输入 | 进入 Mac 的当前直流功率，优先经机型验证的输入遥测 | 一位小数 W，详情注明来源 | 不称墙插交流耗电；无遥测显示 `—` |
| 电池净功率 | 统一为正数充入电池、负数从电池取电 | 菜单栏保留 ±；面板名称随充放电变化 | 遥测或 V×I 二者择一并标来源；不可混拼 |
| 整机耗电 | 设备侧负载遥测；无可靠直接值时，可使用同口径输入减电池净功率估算 | 一位小数 W；派生结果始终带“估算” | 不等于 CPU/GPU 功率；测量边界可含部分转换损耗 |
| 电量 | 当前剩余电量比例 | 整数 % | 与健康度最大容量严格分开 |
| 最大容量 | 系统报告的健康百分比优先；同单位满充容量/设计容量可作单独估算 | “最大容量 100% · 系统报告” | 不能把 CurrentCapacity/MaxCapacity 当作健康度；源切换不连成趋势 |
| 电池状况 | 系统提供的正常/建议维修等状况 | 使用系统语义 | 无状态显示“系统未提供”，不能由单个健康百分比编造诊断 |
| 循环次数 | 系统报告累计循环 | 整数“次” | 不等于插电次数，也不是寿命倒计时 |
| 电池温度 | 经该机型验证单位后的电池传感器数据 | 一位小数 °C | 缺失显示“未提供”；不通过猜测数值大小切换单位 |
| 剩余/充满时间 | 优先系统提供的有效估计 | “约 2 小时 · 估算” | 负数、哨兵值、未知、状态切换显示“正在估算”；暂停充电不显示充满倒计时 |

电压用 V，电流用 A，功率用 W，累计电量用 Wh。mAh 和 Wh 不能直接相除。图内保留负轴，不把放电曲线变成无符号正值。

### 统一功率模型

定义 `P_battery > 0` 为充电，`P_battery < 0` 为放电。

在来源兼容且时间有效时：`P_system_estimate ≈ P_input − P_battery`。

- 充电示例：61.6 W 输入，+27.6 W 进入电池，整机约 34.0 W。
- 插电放电示例：30 W 输入，电池 −15 W，整机约 45 W。
- 电池供电示例：电池 −12.4 W；若缺少整机负载传感器，整机可显示“约 12.4 W · 估算”。

这些是产品解释样例，不是精确物理守恒声明。传感器窗口、转换损耗和测量边界可能不同。差值异常时不硬凑等式、不把负值裁成零后伪装正常。

### 数据质量

每个指标都携带 `value / unit / source / sampledAt / quality / unavailableReason`。quality 至少包括：`reported`（系统报告）、`telemetry`（设备遥测）、`estimated`（估算）、`stale`（过期）、`unavailable`（不可用）。不同指标可独立缺失。

同一次 IORegistry 读取也不保证硬件内部各字段同时更新。因此，“时间接近”是派生计算的必要条件，但不是充分条件；还需要机型、来源和供电状态验证。未验证的测量边界不得呈现精确的能量分配比例。

## 4. 产品结构

| 层级 | 内容 | 用户成本 |
|---|---|---|
| 菜单栏 | 电池状态图标 + 单个固定口径的功率 | 不点击即可看到 |
| 实时面板 | 供电状态、输入/电池/整机功率、电量、迷你趋势、健康摘要 | 一次点击 |
| 趋势页 | 15 分钟 / 1 小时 / 24 小时，三条功率线按需选择 | 面板内切换 |
| 健康页 | 系统状况、最大容量、循环、温度/容量详情、长期记录 | 面板内切换 |
| 独立详情窗 | 更大趋势图、会话摘要、数据导出 | 从趋势页打开 |
| 设置窗 | 菜单栏指标、外观、启动、采样、历史、通知 | 齿轮进入 |

默认不显示 Dock 图标。设置和详情窗口可独立关闭，不退出常驻程序。退出位于菜单栏右键菜单和设置“关于”页。

## 5. 菜单栏规则

默认显示单色模板图标和整机耗电，最多一位小数，例如 `34.0 W`。此值表示 Mac 当前运行的总功率，充入电池的功率另列；不可用或过期时显示 `— W`。

供电状态由图标表达，指标名称由悬停提示和 VoiceOver 说明；不会在拔电后把“输入功率”静默替换为“电池放电”。设置里可改为电池净功率、输入功率，或只显示电量，已保存的选择继续保留。电池净功率保留正充负放的符号；选中输入功率且未插电时显示 `未接入`。

等宽数字、稳定宽度，避免读数抖动导致整条菜单栏移动。鼠标悬停提示包含指标全名、数值、来源、更新时间。菜单栏保持单色模板图标，异常不闪烁。

## 6. 供电状态与优先级

数据不可用/过期优先提示；在有有效数据时，再判断供电状态。刚插拔进入短暂“正在更新”，不沿用旧读数解释新状态。

| 状态 | 展示文案 | 功率流向 / 行为 |
|---|---|---|
| 外接充电 | 外接电源 · 正在充电 | 电源 → 整机；电源 → 电池 |
| 电池供电 | 电池供电 | 电池 → 整机；电源显示“未接入” |
| 外接且已满 | 外接电源 · 已充满 | 电源 → 整机；电池静止 |
| 外接且系统明确暂停 | 外接电源 · 充电已暂停 | 展示系统给出的原因；无倒计时 |
| 外接、不充电、原因未知 | 外接电源 · 当前未充电 | “系统未提供原因”；不用“优化充电”替代未知 |
| 外接且电池持续放电 | 外接电源 · 电池正在补充供电 | 电源和电池共同流向整机；持续后提示 |
| 供电状态切换 | 正在更新供电状态 | 隐去旧派生功率，稳定后恢复 |
| 瞬时近零 | 电池几乎未充放电 | 不凭单个 0 值判定满电或暂停 |
| 部分指标缺失 | 可用指标照常显示 | 缺失项 `—` + 可展开原因 |
| 采集过期 | 数据暂未更新 | 显示最后更新时间，停止流动动画 |
| 无内置电池 | 此 Mac 没有内置电池 | 解释当前版本范围，不显示 0% 健康度 |

产品默认去抖提案：供电事件即时补采；状态切换至少两个有效样本确认。近零阈值暂定 |P_battery| < 0.5 W，持续 10 秒后进入稳定显示；仍保留原始值供历史使用。具体阈值由设备验证调整。

“电池补充供电”是观测描述；只有有效数据持续至少 30 秒，才给出“当前外部供电可能不足以覆盖用电”的辅助说明。不能由一次尖峰诊断充电器或线材损坏。

## 7. 历史与健康

实时页只展示最近 15 分钟的电池功率；趋势页可选输入、整机、电池三路，统一单位 W，电池保留正负号，零轴固定可见。颜色和线型同时区分曲线。

睡眠、退出、无权限、缺失、来源变化均形成断点，不用直线补齐。超过采样间隔三倍的缺口不参与累计 Wh。图表显示记录覆盖率；不足完整时段时明确写“已记录部分”。电池充入与放出的 Wh 分开累计，不只展示两者相减后的净值。

P0 提供最近 24 小时查询与当前区间 CSV；默认本地保留 7 天分钟汇总。后续支持 7/30 天功率趋势。健康数据每天最多记录一个同来源快照，默认保留 90 天，不因频繁采样制造“健康度实时变化”。

健康页把“最大容量 100%”与“剩余电量 65%”分开展示。循环上限仅在匹配官方机型资料时显示参考值；不画剩余寿命倒计时，不因每日 1% 波动提示电池损坏。

首次打开健康趋势显示“还没有足够的历史记录”，展示已开始记录的日期，不生成演示曲线。更换电池或指标来源变化后另起记录段。

## 8. 设置与提醒

设置包含：菜单栏指标与电量显隐；随系统/浅色/深色；登录时启动（首次默认关闭）；标准/省电采样；记录历史开关与保留天数；导出与清除历史；提醒开关。

首启直接展示实时数据，并用一次性轻提示解释“+ 为充电，− 为放电”。不设置账号或全屏引导。未开启提醒时不申请通知权限；需要导出时再打开文件保存面板。

提醒默认关闭，可单独开启低电量、充至指定电量、插电持续放电。应用内状态提示不依赖通知授权。相同条件每次状态周期最多提醒一次，条件解除后再重新武装；阈值附近采用滞回，避免来回通知。

清除历史是唯一需要确认的常规设置动作，弹窗说明将删除的范围。登录启动等可逆设置直接生效。

## 9. 采样与隐私

面板打开时目标 1 秒采样；收起后标准模式 5 秒、省电模式 15 秒。源变化立即补采。健康报告低频更新，睡眠不主动唤醒，唤醒后先重新获取状态。

主读数使用最近约 3 秒的温和滤波；方向判断参考有效原始值与持续时间。历史分钟汇总保留均值、最小、最大、覆盖时间和来源，不仅保存平滑后的曲线。页面可显示“刚刚更新”，不每秒播报给辅助技术。

所有历史默认本地保存，首版无账号、无数据上传。导出的诊断资料仅含机型、系统版本、数据来源与指标，不包含序列号、用户名或硬件唯一标识。

## 11. 验收标准

1. 首次使用者能在 5 秒内说清当前供电来源，并区分供电能力与当前输入；用 5 位目标用户做任务验证。
2. 正负方向、单位换算、缺失值、过期数据、健康度分母和历史积分分别有数据夹具验证。
3. 真实设备完成插拔、低功率输入、暂停/满电、快速切换、睡眠唤醒的对照；没有硬件条件时明确记录未覆盖项。
4. 实时功率与独立 USB-C 功率表对照时记录两侧测量位置与采样窗口，不把不同边界的差额直接判成程序误差。
5. 所有指标详情可追溯来源和时间；没有数据时不存在伪零值或虚假精度。
6. 键盘、VoiceOver、增大对比度、减少透明度、减少动态效果、浅深色与多显示器均可用。
7. 性能目标：收起时 10 分钟平均 CPU < 0.5%（按系统单核 100% 口径）、常驻内存 < 80 MB、睡眠期间不主动唤醒；均为待测目标，发布前用原生构建验证。
8. 退出停止采样；删除历史可回读确认；关闭记录后不再持久化新功率数据。

## 12. 当前设计决定与交付状态

用户已选定方案 1 · Power Path，要求深色、浅色和跟随系统；默认跟随系统。其余沿用：中文、原生交互、只读、Apple Silicon 优先。按本机试用反馈，菜单栏默认指标改为整机耗电；用户仍可选择其他指标。

原生开发版已包含菜单栏、真实采集、实时/趋势/健康页、指标解释、三态主题、本地历史与 CSV，并接入默认关闭的系统通知和登录启动。网页原型继续保留为设计对照，其读数仍是示例。三秒平滑、十秒近零合并、充电会话对比和曲线逐点键盘查看尚未实现；温度与原始容量因单位/接口未验证而不展示值。实际通过项、性能结果和硬件场景空白见 [原生验收记录](native-acceptance.md)，不以功能已编码替代完整验收。
