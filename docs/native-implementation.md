# 原生实现说明

实现日期：2026-09-23。产品为只读 macOS 菜单栏程序，代码目标 macOS 14+，本机实际验证范围见 [验收记录](native-acceptance.md)。

## 结构

| 模块 | 职责 |
|---|---|
| `PowerCore` | 指标模型、单位与符号、来源约束、状态确认、分钟历史、充放电量积分、CSV、偏好与提醒规则 |
| `PowerHardware` | IOKit/IOPowerSources 只读采集、电源变化事件、低频系统健康报告 |
| `MacPower` | AppKit 菜单栏与窗口，SwiftUI 页面，Swift Charts 曲线，采样调度、本地保存、主题、导出和可选系统服务 |
| `MacPowerProbe` | 输出经过筛选的实时诊断 JSON，不输出序列号、UUID 或完整系统报告 |

没有第三方运行时依赖；参考了既有开源工具的数据思路，没有复制其代码。网页原型保留在 `prototype/` 作为设计对照。

## 数据口径

- 输入、净电池和负载优先读取同次 `AppleSmartBattery.PowerTelemetryData` 的 `SystemPowerIn / BatteryPower / SystemLoad`，以 mW → W 转换，保留来源和采样时间。
- 电池净功率统一正充负放。兼容 IORegistry 用无符号整数表达的二进制补码负值，不把负数转成巨大正数。
- 缺失电池遥测时使用同次 `Voltage × InstantAmperage`，显式标注估算。
- 拔电后固件字段可能暂时保留插电读数。因此输入依据明确的外接断开状态显示 0；电池与整机使用当次负电流估算。正电流尚未更新时留空，不沿用旧充电功率。
- 只有同批且同类遥测可用、差值合理时，才用输入减电池估算整机。不会从供电能力补出输入，也不会混用 V×I 与另一套遥测补齐等式。
- 健康度每小时读取一次系统健康报告；温度、设计/满充容量在单位与接口未完成验证时不展示猜测值。
- 外部电源状态变化先显示“正在更新”，下一次一致样本才恢复功率展示。没有系统明确原因时显示“当前未充电”，不猜测优化充电或暂停原因。
- 当前读数保持原始方向与一位小数显示；未加入原设计提案中的三秒平滑与十秒近零合并，以免隐藏短时变化。这两项属于后续可选优化，未冒充已经完成。

上述私有遥测键不是 Apple 的跨机型稳定性承诺；当前机器之外需要建立实机兼容矩阵。

## 采样与存储

面板或详情/设置窗口打开时每 1 秒采样；全部收起后 5 秒，省电模式 15 秒。硬件读取在后台执行且不重叠；电源事件额外触发读取。系统睡眠通知停止定时器、断开历史连续性，唤醒立即重读。健康报告有 12 秒超时。

历史位置：`~/Library/Application Support/MacPower/history-v1.json`。偏好使用应用自己的 `UserDefaults`（`app.macpower.local`）。历史按分钟聚合，保留每项有效样本算术均值、最小、最大、样本量、质量和来源；能量按相邻有效样本及真实时间间隔积分。跨零分别累计充入/放出 Wh；大于采样间隔三倍、供电变化、来源变化、停采和重启均形成断点。绝不跨缺口补电量。

默认保留功率记录 7 天，可选 30/90 天；健康记录每天同来源最多一条、保留 90 天。采用原子文件替换，正常运行约每分钟落盘，退出再保存一次；异常退出可能丢失最近不足一分钟的记录。读取损坏文件时保留原文件并明确提示，不直接覆盖；用户清空时先备份损坏文件。

没有账号、网络上传或管理员辅助进程。原始系统信息输出可能含硬件标识，仅在内存中筛选健康字段，不写入历史、CSV 或诊断 JSON。

## 外观与窗口

跟随系统 / 浅色 / 深色是保存的三态枚举；通过 `NSApp.appearance` 与窗口/弹层 appearance 实现，跟随系统使用 `nil`，不修改 macOS 外观。菜单栏图标始终是系统单色模板。

实时、趋势、健康在菜单栏弹层内切换；设置、完整趋势和指标解释使用独立原生窗口。固定窗口尺寸由 AppKit 管理，页面中的长内容独立滚动，避免切换到趋势时窗口收缩。完整趋势继承当前时段和曲线选择。

点击图钉或再次从 Finder 打开程序，会显示可独立关闭的概览窗口，便于菜单栏拥挤时访问。关闭窗口和 ⌘W 不退出采集，⌘Q 或右键菜单/“关于”退出。启动时打开一次实时弹层，随后收起仅留菜单栏。窗口和弹层关闭时释放其 SwiftUI 页面与图表，后台仅保留数据与菜单栏。

可选登录启动使用 `SMAppService`；可选提醒使用系统通知。默认均关闭，用户主动打开提醒时才请求权限。充至指定电量仅通知，不改变充电策略。

## 构建与测试

```sh
zsh scripts/test.sh
zsh scripts/build-app.sh
```

输出：`build/MacPower.app`。当前构建脚本使用本机临时签名并校验完整性，适合本机开发验收；不等于 Developer ID 签名和 Apple 公证，也未制作 App Store 沙盒版本。

本机为 Swift 6.4 / macOS 27 SDK 的 Command Line Tools 环境。SwiftUI `State` 新宏与旧属性包装类型重名，但工具链缺少该新宏插件，因此用 `ViewState` 类型别名明确引用可向旧系统部署的属性包装类型。Swift Testing 的宏插件位于嵌套目录，测试脚本显式提供该路径。没有绕过系统安全检查或要求安装完整 Xcode。
