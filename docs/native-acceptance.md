# MacPower 0.1.0 原生验收

日期：2026-09-23，Asia/Hong_Kong。交付对象：`build/MacPower.app` 本机开发版。

结论：核心功能已实现，完成本机数据、自动测试、原生页面及真实 CSV 落盘验收。性能与兼容性按以下测量范围记录，尚不满足“所有发布前验收均通过”的条件。网页原型验收独立保留在 `design-qa.md`。

## 环境与构建

- Apple Silicon MacBook Pro，M4 Pro / Mac16,8，macOS 27.0 (26A428)，arm64。
- Swift 6.4 Command Line Tools；代码部署目标 macOS 14，未在 macOS 14/15 或 Intel 实机验证。
- Release 构建成功，应用包具备 Info.plist、原生图标和 LSUIElement 菜单栏配置。本机临时签名通过严格完整性检查。
- 没有安装管理员辅助进程，没有自动注册登录项或请求通知权限。应用保持只读监测。

## 测试发现与修复

1. 主题选择曾触发 `@Published preferences` 的 observer 内自赋值，造成递归崩溃。最小复现和崩溃调用栈定位后，移除 observer 中的回写，仅在读取偏好时验证；原生浅/深/系统连续切换和重开复验通过。
2. SwiftUI 的滚动内容固有高度使独立概览切到趋势时收缩。改为 AppKit 管理尺寸、关闭自动尺寸反推并约束根视图；实时 → 健康 → 趋势切换后窗口保持完整高度。
3. 菜单栏程序缺少标准窗口快捷键。补充“窗口”菜单的关闭/最小化动作，并实测 ⌘W 返回原窗口。
4. 收起后仍保留页面和图表。改为关闭时释放 SwiftUI 承载视图，重新打开时按需创建；主题与记录保留在数据层。
5. 原先 50 MB 的历史读取上限可能拒绝正常 90 天记录，改为匹配 140,000 条记录上限的 256 MB 容量保护。大规模长期历史的性能仍待单独测量。
6. 时间轴末端标签裁切、浅色下电量进度未遵循语义色、满电图标仍用固定 75% 图形，均在最终版本修正并截图复验。电流回退字段的来源名称也改为实际使用的字段，并增加测试。

## 后台与性能

10 分钟测量见 `build/evidence/background-verification.json`，环境及对应二进制摘要见 `acceptance-environment.json`。采样时先实际打开实时、趋势和设置，再关闭所有窗口，期间不打开应用界面。

| 指标 | 实测结果 | 判定 |
|---|---|---|
| 观测时长 | 600.038 秒 | 完成 |
| 平均 CPU（单核 100%） | 0.3566% | 低于 0.5% 目标 |
| RSS 初始 / 结束 / 峰值 | 144.33 / 143.80 / 144.33 MiB | 高于 80 MB 目标，不通过 |
| 后台 physical footprint 两次快照 | 55.9 / 56.0 MiB | 单独报告，不替代 RSS；不是连续峰值 |
| 新增落盘样本 | 122 次，历史文件由 25,183 增至 33,132 字节 | 后台记录与持久化继续运行 |
| 供电来源变化 | 外接电源转为电池供电；来源段变化 | 断开旧来源连续性，无假拼接 |

测量采用累计进程 CPU 时间除以真实经过时间，单核 100% 口径；每 5 秒记录 RSS，同时检查磁盘历史样本增长。RSS 包含驻留的共享框架等页面；另用系统 `vmmap` 记录 physical footprint，二者分别报告。生命周期 footprint 峰值 174.5 MiB 包含界面操作，不能称作后台峰值。测量期间运行过只读内存诊断，未扣除可能产生的诊断开销。

10 分钟测量之后只进行时间轴/进度条/图标、趋势选择继承和来源标签收尾，采样与持久化实现未改变；最终包另做界面复验和短时后台回归，保留两个版本的证据，不将它们混成同一次运行。

最终包后台回归见 `background-final-smoke.json`：120.024 秒内平均 CPU 0.2999%，新增落盘 25 次采样，RSS 保持 154.375 MiB。该次先打开完整趋势等更多页面再收起，内存结果同样未通过 80 MB RSS 目标；无崩溃或持续增长的证据也不等于证明不存在长期泄漏。

最终包后台 physical footprint 快照为 61.3 MiB，含界面操作的生命周期峰值 177.0 MiB，见 `memory-final-bundle.json`。该数值与 RSS 继续并列保留。

原设计“常驻内存 < 80 MB”未明确测量口径，本验收不将较低的 footprint 替代较高的 RSS 以宣称全部通过。短时过程也不代表整日耗电、内存泄漏长期检验或 90 天历史规模性能。

## 仍未完成的发布前验证

| 范围 | 当前边界 |
|---|---|
| 快速反复拔插、低功率供电、优化充电/暂停、睡眠唤醒、多显示器 | 相关逻辑有实现与部分夹具覆盖，已被动观察一次真实电源来源改变，未操作用户硬件或睡眠电脑完成全矩阵 |
| 其他芯片、旧版系统、无内置电池、外设/UPS | 未建立实机兼容矩阵；无服务显示不可用，不补成 0 |
| 独立测量准确性 | 未接 USB-C 功率表；当前只证明与系统字段的转换一致 |
| 通知、登录启动 | 已接系统 API，默认关闭；未授予权限或注册登录项完成端到端验证 |
| 完整无障碍 | 提供语义标签和系统控件；尚未完成 VoiceOver、增强对比度、减少透明度和键盘全流程验收 |
| 大规模与长期稳定性 | 10 分钟后台观察不替代 24 小时运行或 7/30/90 天历史负载测试 |
| 正式发布 | 尚无 Developer ID、Apple 公证、通用二进制、安装器或自动升级链路 |

当前可供本机试用与继续迭代；不把尚未验证的能力标为通过。
